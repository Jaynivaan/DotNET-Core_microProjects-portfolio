# Day06-WeatherApi

---

### Objectives

The goal of this project is to build a weather client api using ASP.NET Core
andto learn how external systems communicate with apis.

This project focusses on 

- External API communication
- Modern backend .NET Architecture.
- Secure by default engineering.
- Resilient System Design.
- Future-ready performance Awareness.

---

### Planned Features

--Fetch Weather data from external API
 
--Accept  city name as input

--Return structured json Resonses.

--Handly invalid city request safely.

--Use Service based Architecture.

--Use Dependency Injection.

--Use IHttpClientFactory instead of raw HttpClient creation.

---

### My learning Intentions.

*** Understand External API communications

*** Learn Modern HttpClient Architecture.

*** Learn async/await flow deeply.

*** Understand service Separation.

*** Learn secure Backend communication Principles

*** Build resilient Engineering Habits from the beginning.

*** Learn how scalable systems are structured.
 
---

### Modern Engineering Directions

This project intentionally avoids outdated backend patterns whereever possible.
Instead of using simplistic and tightly coupled methodologies,,

=using `IHttpClientFactory`
=using dependency injection
=using service classes
=using structured responses.
=prepare for resilient patterns
=Build secure by default apis


### Thought Chain

+modern systems constantly communicate with external systems.
+external apis are unreliable by nature.
+backend should fail gracefully.
+never trust external responses blindly.
+system should expose minimal internal details.
+secure architecture should begin from project planning itself.
+directory structure matters for scaling.
+services should be separate from the endpoints.
+AI systems can rapidly discover weak patterns in badly designed systems.
+therefore archetecture should be intentional from the beginning.
